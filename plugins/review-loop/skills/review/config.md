# Project settings for `review-loop:review`

Put a `## Review harness` section in the repository's `CLAUDE.md`. The skill reads it at the start of every run. Nothing is parsed mechanically — the model running the skill reads the section — so a little formatting drift is fine, but keep the key names below.

Every key is optional. A missing key uses its default.

| Key | Meaning | Default |
|---|---|---|
| `verify` | Commands to run after fixing, all of them, every round. A sub-bullet can say why a command must not be skipped. | Inferred from the repository (`package.json` scripts, `Makefile`, `pyproject.toml`, …) and announced before round 1 |
| `protected_tests` | Tests whose failure means the finding is probably wrong, not the test. | None (the general rule "never skip or delete a test to get green" still applies) |
| `language` | Language for PR comments and replies. | The language of the PR description |
| `footer` | Text appended to every comment and reply. | A blank line, `---`, then `_Generated by [Claude Code](https://claude.ai/code)_` |
| `commit_message` | Message for a round's fix commit. `N` is replaced by the round number. | `Address review findings (round N)` |
| `effort` | Default `/code-review` level. | `medium` |
| `rounds` | Default round limit. | `3` |
| `ci_review` | `none`, or `claude-code-action` if `anthropics/claude-code-action` with the code-review plugin reviews PRs automatically. | `none` |

## Example

```markdown
## Review harness
- verify: `npm run lint`, `npm run test`, `npm run build`
  - Never skip build: importing a server-only module from a Client Component passes the tests and fails only `next build`.
- protected_tests: `lib/articles/queries.test.ts`, `lib/questions/queries.test.ts` (they pin the read-side sanitization boundary)
- language: ja
- commit_message: レビュー指摘を修正する（第 N 周）
- ci_review: none
```
